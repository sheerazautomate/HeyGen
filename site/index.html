Setup guide

1 Enable GitHub Pages

In your repository: Settings → Pages → under Build and deployment, set Source = GitHub Actions. Then run Actions → Deploy site to GitHub Pages → Run workflow (it also runs on every push to main that touches site/ or examples/).

2 Choose a render engine

  • HeyGen cloud (default when available): add your API key as the repository secret HEYGEN_API_KEY under Settings → Secrets and variables → Actions. Renders run on HeyGen's infrastructure via POST /v3/hyperframes/renders. Get a key from the HeyGen API dashboard.
  • Runner render (fallback, free, no key): the workflow renders inside GitHub Actions with the open-source hyperframes CLI (headless Chrome + FFmpeg on the runner).
  • Engine auto = cloud when the secret exists, otherwise runner.

3 Create a browser token

The page needs a personal access token to (a) upload your HTML as a git blob and (b) dispatch the render-video workflow. A fine-grained token with Contents: Read and write + Actions: Read-only on this one repository is the least-privilege choice. Paste it in the Composer tab — it never leaves your browser except to api.github.com.

How a render flows

  POST /repos/{owner}/{repo}/git/blobs          ← script.html as a git blob
  POST /repos/{owner}/{repo}/dispatches         ← event: render-video (blob sha + settings)
        │
        ▼
GitHub Actions · “Render HyperFrames video”
  prepare:  fetch blob → build/project/index.html   (lint: hyperframes lint)
  render:   A) HeyGen cloud  — zip → POST /v3/hyperframes/renders → poll → download
            B) runner       — npx hyperframes render (headless Chrome + FFmpeg)
  publish:  gh release create video-<run>-<key>  (video + thumbnail + script.html)
        │
        ▼
Releases tagged video-*  →  listed & playable right here in the Videos tab

FAQ & troubleshooting

The render failed — where are the logs?
The progress card links to the exact Actions run. Open it, click the render job, and expand the failed step (usually Render with HeyGen cloud or Render locally in the runner).
No HeyGen API key — can I still render?
Yes. Leave engine on auto or pick Actions runner; the open-source CLI renders in the workflow at no HeyGen cost.
Preview is blank or the player errors
Previews use the @hyperframes/player web component from a CDN and need network access to it. Rendering is unaffected — the Actions render loads the same scripts server-side.
Where does my composition go?
It is stored as a dangling git blob (not attached to any branch or commit history) and referenced by the workflow run. Nothing is pushed to main.
Run status shows “can’t read runs”
Your token lacks Actions: Read. Renders still work — use the Actions tab link to watch progress.
403 rate limit?
Unauthenticated GitHub API calls are limited to 60/hour. Adding a token raises it to 5,000/hour.
